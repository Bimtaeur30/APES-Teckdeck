# PHASE-003 — 가상 커서 기반 오브젝트 X/Z 이동

## 기본 정보

- 상태: `완료`
- 작성/갱신 일시: `2026-08-13 23:57 (Asia/Seoul)`

## 요청과 목표

- 원래 요청: 가상 마우스가 이동하는 위치에 따라 어떤 오브젝트의 X/Z 위치도 이동
- 이 Phase의 목표: 커서 위치를 이동 영역 내 0~1 좌표로 변환해 지정한 Transform의 월드 X/Z 범위에 대응
- 완료 조건: 대상·범위·축 반전을 Inspector에서 설정할 수 있고 대상의 Y를 유지하며 이동

## 승인된 구현 범위

- 변경 예정 파일: `VirtualMouseUI.cs`, KTJ 작업 기록
- 구현 방법: 커서 Bounds 중심을 이동 가능한 영역에서 정규화하고 `Mathf.Lerp`로 월드 X/Z 좌표 계산
- 검증 방법: C# 컴파일 및 경계·중앙 좌표 계산 검토, Unity Play Mode 수동 확인
- 명시적으로 제외한 항목: 대상 자동 연결, Y 이동, 회전, 클릭 처리

## 구현 결과

- 수행한 작업: 대상 Transform과 월드 X/Z 범위, 각 축 반전 설정 추가. 커서 Bounds 중심을 이동 가능 범위 안에서 정규화해 대상 위치에 반영
- 생성·수정한 파일: `VirtualMouseUI.cs`, `PROGRESS.md`, `PHASE-003.md`
- 계획과 달라진 점 및 이유: 없음

## 학습 노트

- 전체 실행 흐름: 커서 이동·Clamp 완료 → 커서 Bounds 중심 좌표 계산 → X/Y UI 좌표를 각각 0~1로 정규화 → X/Z 월드 범위를 `Mathf.Lerp`로 계산 → 기존 Y를 유지한 채 대상 위치 갱신
- 주요 데이터 역할: `targetObject`는 움직일 대상, `targetXRange`와 `targetZRange`는 월드 이동 한계, `invertX`와 `invertZ`는 각 축 방향 반전
- 중요한 구현 원리: UI의 절대 좌표를 월드 좌표로 직접 복사하지 않고 두 영역 사이의 비율을 대응시켜 Canvas 크기와 월드 이동 범위를 독립적으로 설정
- 예외 상황과 대응: 대상이 없으면 커서만 정상 동작하고, 커서가 이동 영역보다 커 정상 범위를 만들 수 없으면 중앙값 0.5를 사용
- UniTask/DOTween: 매 프레임 즉시 입력을 반영하는 단순 동기 처리라 사용하지 않음

## 검증

- 자동 검증: 새 스크립트를 포함한 `KTJ.csproj` 빌드
- Unity Editor 수동 확인 절차: Cursor의 Virtual Mouse UI에서 Target Object와 X/Z Range를 설정한 뒤 Play. 커서를 좌우·상하 및 네 모서리로 옮겨 대상의 X/Z가 각 범위 끝에 도달하는지 확인. 방향이 반대면 Invert X/Z 사용
- 결과: 빌드 경고 0개·오류 0개
- 검증하지 못한 항목: 실제 대상 오브젝트가 지정되지 않아 Play Mode 이동 결과는 미확인
