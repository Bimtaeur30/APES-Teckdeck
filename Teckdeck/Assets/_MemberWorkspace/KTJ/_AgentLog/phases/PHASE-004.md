## 요청과 목표

- 원래 요청: 오브젝트 위치를 0으로 초기화하지 않고 처음 위치가 중심이 되도록 수정
- 이 Phase의 목표: 대상의 활성화 시점 월드 위치를 저장하고 X/Z 범위를 그 위치 기준 오프셋으로 적용
- 완료 조건: 커서 중앙에서 최초 위치가 유지되고 가장자리에서 최초 위치에 설정 범위를 더한 좌표로 이동

## 학습 노트

- 전체 실행 흐름: 컴포넌트 활성화 시 대상 위치 저장 → 커서 위치를 0~1로 정규화 → 중앙 0.5에서 오프셋 0 계산 → 최초 위치에 X/Z 오프셋을 더해 적용
- 주요 데이터 역할: `_targetStartPosition`은 활성화 시점의 기준 월드 위치이며, `targetXRange`와 `targetZRange`는 절대 좌표가 아니라 기준 위치로부터의 최소·최대 오프셋
- 중요한 구현 원리: 정규화 범위를 좌측/하단 `0~0.5`와 우측/상단 `0.5~1`로 나눠 범위가 비대칭이어도 중앙 오프셋이 항상 0이 되도록 함
- 예외 상황과 대응: 대상이 없으면 위치를 저장하거나 갱신하지 않음. 컴포넌트를 다시 활성화하면 그 시점의 위치를 새로운 중심으로 저장
- UniTask/DOTween: 매 프레임 즉시 입력을 반영하는 동기 처리이므로 사용하지 않음

## 검증

- 자동 검증: Phase 004 변경이 포함된 `KTJ.csproj` 빌드
- Unity Editor 수동 확인 절차: 대상을 임의의 0이 아닌 X/Z 위치에 놓고 Play. 커서를 중앙에 두었을 때 최초 위치인지 확인하고, 좌우·상하 끝에서 최초 위치에 각 Range 값을 더한 위치인지 확인
- 결과: 빌드 경고 0개·오류 0개
- 검증하지 못한 항목: 실제 대상과 설정값을 사용한 Play Mode 동작
