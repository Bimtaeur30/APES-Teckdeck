## 요청과 목표

- 원래 요청: 1/3 해상도 화면의 흐릿함을 줄이고 픽셀 느낌 강화
- 이 Phase의 목표: 178×110 결과를 정확히 3배 확대하고 출력 단계에서 경계와 색상 단계를 선명하게 정리
- 완료 조건: RawImage가 534×330 크기로 표시되고 전용 픽셀 머티리얼이 적용됨

## 승인된 구현 범위

- 변경 파일: 전용 Shader/Material, `RepairShop_KTJ.unity`, KTJ 작업 기록
- 구현 방법: Point 필터 결과에 약한 4방향 선명화와 16단계 색상 양자화 적용
- 검증 방법: Shader 임포트 로그, C# 컴파일, 씬 Material 참조 및 출력 크기 검사
- 범위 밖 항목: 스캔라인, 노이즈, 색수차, 화면 왜곡

## 구현 결과

- 생성·수정한 파일: `RepairShop_KTJ.unity`, 작업 기록. 시험했던 전용 Shader/Material은 최종 구성에 불필요하여 삭제
- 계획과 달라진 점 및 이유: 없음

## 검증

- 자동 검증: `dotnet build KTJ.csproj --no-restore`, 씬 머티리얼 GUID와 원본/출력 Canvas 크기 검사, `git diff --check`, Unity Editor 로그의 Shader 오류 검색
- 결과: 컴파일 경고 0개·오류 0개, 원본 Canvas 534.3×330.8 유지, 출력 Canvas 534×330, RawImage 기본 머티리얼 및 Point 필터 연결 확인
- 검증하지 못한 항목: Scene/Game View에서 사용자가 느끼는 최종 선명도

## 학습 노트

- 전체 실행 흐름: 원본 UI를 178×110으로 캡처 → Point 필터로 보간 없이 3배 확대 → 534×330 RawImage 출력
- 주요 데이터 역할: RenderTexture 해상도가 픽셀 수를 결정하고 RawImage 크기가 화면에서 보이는 픽셀 크기를 결정
- 중요한 구현 원리: 별도 색상·경계 가공 없이 Point 필터만 사용해 각 저해상도 텍셀을 사각형 픽셀 그대로 확대
- 예외 상황과 대응: 출력 크기가 정수 배율에서 벗어나면 픽셀 너비가 균일하지 않을 수 있으므로 534×330 유지
- UniTask/DOTween: 정적 렌더 샘플링이므로 사용하지 않음
